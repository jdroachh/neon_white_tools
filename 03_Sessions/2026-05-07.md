# Session 2026-05-07

## What landed

### YouTube error 153 — fixed (localhost HTTP server)

- Root cause: WebView2 was loading `frontend/dist/index.html` over `file://`, giving the page a null origin that YouTube's embed runtime rejects.
- Fix: `SteamScraper/webview_app/main.py` now spins up a `ThreadingHTTPServer` (daemon thread, random free port on 127.0.0.1) rooted at `frontend/dist/` before creating the pywebview window. Window URL changed from `file:///...index.html` to `http://127.0.0.1:<port>/`. ~30 lines added.
- Confirmed working by user.

### Medal target time display — off-by-1ms corrected

- `get_medal_times` in `bridge.py` returns the exclusive cutoff (e.g. 18.200s for Movement Emerald). A player needs strictly less than that value, so the max qualifying time is cutoff − 1ms.
- Fix in `frontend/src/pages/RouteVideos.jsx`: `displayTarget = targetSecs - 0.001` used in place of raw `targetSecs` for the pill display.

### YouTube iframe error handling

- Added `enablejsapi=1&origin=<window.location.origin>` to the embed URL so YouTube's iframe API can post messages back.
- `window.addEventListener("message", ...)` listens for `infoDelivery` / `onError` events from `youtube.com`; sets `videoError` state on any error.
- When `videoError` is true, the iframe is replaced with a "Could not load video in app / Open in YouTube" fallback. Error resets on row selection change.
- Column header "Title" → "Route" in the video table.
- M4 known bug section removed from `00_Inbox/todo.md`; `00_Inbox/handoff_youtube_153.md` deleted.
