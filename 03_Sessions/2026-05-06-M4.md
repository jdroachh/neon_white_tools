## Known bug — YouTube error 153 inside the embedded player

- **Repro:** any stage on Route Videos, any medal with at least one video. Iframe loads but YouTube renders error 153 ("video player configuration error") instead of playing.
- **Diagnosis:** WebView2 loads `frontend/dist/index.html` over `file://`. The iframe's referrer is then `null` / `file://`, and YouTube's embed runtime rejects it for many videos. First attempted fix (this session) — switch from `youtube-nocookie.com` to `youtube.com/embed/`, add `playsinline=1 modestbranding=1`, and `referrerPolicy="strict-origin-when-cross-origin"` — was inconclusive at end of session. User reported error 153 with the nocookie domain; the change to plain youtube.com was deployed but the user hasn't re-tested before stopping for the evening.
- **Next attempts to try, in order:**
  1. Re-test plain `youtube.com/embed/…` once the user reopens the app (the change is in `dist/bundle.js` but the running instance was started before it). May already be fixed.
  2. Add `&origin=<...>` and `&enablejsapi=1` query params with a synthetic origin matching whatever `document.location.origin` resolves to inside WebView2.
  3. Stand up a minimal localhost HTTP server in `webview_app/main.py` (`http.server.ThreadingHTTPServer` on a random free port, root = `frontend/dist/`) and load the window from `http://127.0.0.1:<port>/` instead of `file://`. This fixes the referrer story permanently and is the recommended long-term path. ~30 lines.
  4. As a last resort: render a thumbnail + "Open on YouTube" link instead of an inline player.
- **Workaround in the meantime:** the per-row "Open in YouTube" button works fine — opens the video in the user's default browser via the existing allow-listed bridge call.
