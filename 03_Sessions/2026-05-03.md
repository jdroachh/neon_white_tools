## Rush Seed Finder bug fixes (same day)

Headless test (`SteamScraper/_seed_finder_test.py`) confirmed three bugs and surfaced a UX issue. All four fixed in `neonwhite_app.py`:

1. **Workers ran pure-Python shuffle** (lines 400, 460). On Windows-spawn child processes, `_SHUFFLE_LIB` stayed `None` because `_load_c_shuffle()` is only called from `NeonWhiteApp.__init__`. Fix: call `_load_c_shuffle()` at the top of `_seed_search_worker`. Verified speedup: **29k → 76k seeds/sec per worker**.
2. **Progress bar never moved during search** (manager loop, ~line 1303). Old code computed `done_workers / num_cores`, so progress was 0% until first chunk finished. Fix: workers now push `("progress", count)` messages every 200k seeds; manager sums `seeds_checked / TOTAL_SEEDS`. Status bar now shows `Searching... X of 2,147,483,647 seeds checked, Y found`.
3. **`urlopen()` misplaced in worker** (old lines 414–419). Each worker hit `COMMUNITY_MEDALS_URL` after finishing its chunk for no reason. Deleted.
4. **No warning for statistically infeasible searches.** Added `_expected_match_count()` helper. `_run_finder` now shows a Yes/No dialog if expected matches across the 2.1B range is < 10. For (96 levels, 12 targets, depth 25) the expected count is ~17.88, just above threshold; (96, 12, 40) gives ~19,206.

Test harness left at `SteamScraper/_seed_finder_test.py` for re-running after future changes.
