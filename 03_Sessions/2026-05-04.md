## Pattern / lessons

- **Lazy-imports for circular deps.** `tab_settings.py` needs `save_config` (defined in core). Top-level `from neonwhite_app import save_config` would loop. In-method `from neonwhite_app import save_config` works because by the time any settings method is *called*, the core module has finished loading. Cheap, local, and only at the two real call sites. Pattern to remember if other mixins ever need a core utility.
- **TOKEN_FILE was already a "duplicated on purpose" constant** in core to avoid pulling `sheets` at startup. The same constraint applies in `tab_settings.py` — duplicated again with the same comment. Acceptable because the constant is one short string and the alternative (eager `import sheets`) would re-introduce the slow startup the previous extraction round was designed to avoid.
- **Sidebar order matters.** Every other tab's `_build_*_section` creates `self.<key>_frame`, and `_show_section` reads that map. The build order in `__init__` builds tab frames first, then `_build_sidebar` last; that order is preserved across the extraction.

## Session 2 — `find_seeds_batch` C batch search (todo item #4)

### What changed

- **`compile_shuffle.py`**: added `find_seeds_batch` to `C_CODE` next to `full_shuffle`. Adds `#include <stdint.h>`. Extended `verify_dll()` with a smoke test (cross-checked against `full_shuffle` over 1k seeds). Rebuilt `shuffle.dll`.
- **`shuffle_lib.py`**: registered `find_seeds_batch` argtypes/restype; added Python wrapper that raises on missing DLL.
- **`seed_search.py`**: rewrote `_seed_search_worker` to call `find_seeds_batch` in 250k-seed slabs. Queue protocol unchanged.

### Measured speedup

- Old path: ~89k seeds/sec (ctypes allocation + `list()` round-trip + `issubset` per seed dominated)
- New path: ~1.1M seeds/sec (one ctypes boundary crossing per 250k seeds; C does the full loop)
- **~12× end-to-end speedup**
- Stop latency: ~234ms (well within 500ms budget)

### Deviations from design doc

Three design doc values needed correction:

1. **`arr[64]` → `arr[128]`**: design doc said 64, but White rush uses 96 levels. Would have silently overflowed the stack.
2. **Single `uint64_t target_mask` → `target_mask_lo` + `target_mask_hi`**: `1ULL << N` with N≥64 is UB in C; on x86 the shift wraps mod 64, causing false positives for seeds where a level with index 64+ appears in the first `depth` positions. Split into two 64-bit masks covers up to 128 levels safely.
3. **`SLAB_SIZE` 1,000,000 → 250,000**: a 1M-seed slab at 1.1M seeds/sec takes ~910ms > 500ms stop budget. Design doc noted 250k as the fallback tuning — applied it.

### Verification

- DLL smoke test passes (20 matches in seeds 0–999 cross-checked against `full_shuffle`)
- Correctness: 8-level and 96-level workers produce identical match lists to `full_shuffle`-based reference
- Stop test: PASS (234ms)
- `full_shuffle` unchanged; `tab_rush_parser`, `tab_rush_splits`, `tab_rush_std`, `tab_rush_timer` all import cleanly
