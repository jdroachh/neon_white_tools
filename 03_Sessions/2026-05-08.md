### Bug fixes during testing

**Bug 1 — URL space rejected by urllib (`HTTP Error: URL can't contain control characters`)**
- `_WR_TAB = "WR Import"` contains a space; `_csv_url` was interpolating it raw into the URL.
- Fix: added `from urllib.parse import quote` and changed `_csv_url` to `f"...&sheet={quote(tab)}"`. All three sheet fetches now use the same URL-safe function.

**Bug 2 — Row count mismatch (`expected 121 data rows, got 120`)**
- The plan described 2 header rows (banner + column headers), so the loader did `rows[2:]`. In practice the GViz CSV endpoint omits the banner row entirely and treats the column-name row as row 0, so only 1 header row is present.
- Fix: changed `rows[2:]` → `rows[1:]`. Verified with a live fetch: 121 data rows, all three canaries pass, Pummel PC = Hyuniko 5.458 ✓.

**Bug 3 — "Watch" button opened browser instead of embedding video**
- Initial implementation used `openExternalUrl` (external browser), but Route Videos embeds a YouTube iframe inline. Users expected the same in-app playback.
- Fix: rewrote `WorldRecordVods.jsx` to use the identical iframe embed pattern from `RouteVideos.jsx` — 16:9 `paddingTop` container, `enablejsapi=1&origin=...` embed URL, `window.message` listener for YouTube API errors, fallback "Could not load video in app / Open in YouTube" overlay. Runner/time/date/title bar sits below the iframe.

**Also fixed — stale `wrs_loaded` state on fast navigation**
- `getResourcesStatus()` was called once on mount; if the WR background fetch completed after that, the page showed "Loading resources…" indefinitely.
- Fix: re-poll `getResourcesStatus()` inside the `getWorldRecord` `.then()` chain so status refreshes on every level/platform change.

### Root cause of the initial-load bug

On mount: `getResourcesStatus()` returned `wrs_loaded: false` (Python sheet fetch not done). `getLevels()` resolved → set level → triggered `getWorldRecord` → Python returned `null` (not ready) → status re-polled still false. Python finished loading moments later but frontend had no signal and no retry path. Fix: self-cancelling `setTimeout` polling loop keyed on `[status.wrs_loaded, status.error, level, platform]`.
