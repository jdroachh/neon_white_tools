# 2026-05-10 — Community Guides: Watchlist / Watched markers

## What shipped

**Backend (`SteamScraper/webview_app/bridge.py`)**
- Added `guide_watchlist`, `guide_watched`, `guide_hide_watched`, `guide_watchlist_only` to `_DEFAULT_CONFIG`.
- Added `_CONFIG_LOCK` (threading.Lock) around all config I/O — `_load_config_raw` / `_save_config_raw` as internal helpers, public `_load_config` / `_save_config` for read-only callers.
- `save_config_field` now holds the lock across the full read-modify-write (no interleave window).

**Frontend (`frontend/src/pages/Guides.jsx`)**
- `watchlist` + `watched` merged into single `watchState` object; `handleCycle` uses functional `setWatchState(prev => ...)` — rapid clicks no longer read stale closure state.
- Single `saveConfigFields(...)` call per click — both arrays written atomically.
- Filter toggles (`hideWatched`, `watchlistOnly`) now persist via config and hydrate on mount.
- `WatchCycleBtn`: ○ (dim) / ✓ (accent) / ✗ (red `#f87171`).
- `fetchFailed` now gated on `guidesLoaded` — "couldn't load" only shows if the sheet actually returned empty after loading, not during the race window.
- Polling loop added: if guides come back empty on mount, retries every second until `guides_loaded` flips.

**Frontend (`frontend/src/pages/RouteVideos.jsx`, `Ghosts.jsx`)**
- Added same polling pattern as `WorldRecordVods.jsx` — "Resources not loaded" dead-end replaced with "Loading resources…" that auto-populates once the background fetch finishes.

**`frontend/src/api.js`**
- New `saveConfigFields(fields)` export.
- New `getResourcesStatus` import used by Guides polling.

- "Resources not loaded" on first page visit (Route Videos, Ghosts) — fixed by polling.

# 2026-05-10 (later still) — Beta build shipped to distribution

Built and smoke-tested `v1.11.0-beta.1`. Final size **38.2 MB** (well under the 60–90 MB the legacy spec was producing).

## Spec rewrite (`SteamScraper/neonwhite.spec`)
- Stripped 8 Google SDK `collect_all()` blocks + `runtime_hooks=['rthook_google.py']`.
- Added Google libs to `excludes` as belt-and-suspenders.
- Hidden imports pruned to a 5-entry stdlib subset.
- **Switched onefile → onedir** (`EXE(exclude_binaries=True)` + `COLLECT()`). Required for log/config persistence — onefile extracts to a temp dir that's wiped on close, which would have made the tester diagnostics useless.
- Bundled `shuffle.dll` via `binaries=[('shuffle.dll', '.')]` — legacy spec had never bundled it; would have crashed the seed finder in any frozen build, ever.

## Code-side fixes for frozen mode
Multiple `__file__`-relative paths were broken in the bundle. Audit + fixes:

| File | Change | Reason |
|---|---|---|
| `logger.py` | `_HERE` uses `sys.executable`'s dir when `sys.frozen` | Logs land next to EXE, not inside `_internal/` |
| `webview_app/bridge.py` | `_CONFIG_DIR` uses `sys.executable`'s dir when frozen | `neonwhite_config.json` persists next to EXE; testers can edit/reset |
| `webview_app/main.py` | `_DIST_DIR` uses `sys._MEIPASS` when frozen | Frontend assets live in `_internal/frontend/dist/` in onedir PyInstaller 6+ |
| `shuffle_lib.py` | `dll_path` uses `sys._MEIPASS` when frozen | Bundled `shuffle.dll` lands in `_internal/`, not source dir |
| `webview_app/main.py` | Added `multiprocessing.freeze_support()` | Required on Windows; without it seed-finder worker spawn re-executes the whole app |

## New launcher: `SteamScraper/run_app.py`
PyInstaller runs the entry script standalone, which breaks `from .bridge import ...` (no parent package). Added a thin launcher that:
1. Calls `multiprocessing.freeze_support()` first (so worker spawns exit before re-importing `bridge.py` + medal data fetch + resources thread)
2. Then imports `webview_app.main._main` as a package member
3. Calls `_main()`

Updated spec entry to `['run_app.py']`. Dev launch (`python -m SteamScraper.webview_app.main`) still works unchanged — the launcher is frozen-only.
